# Flip sync-token source of truth to the extension

## Context

`firebasePlan.md` originally flagged that the second firebase commit had
linking "the wrong way (generated by web)". This session already gave the
extension its own token generator (Generate + Copy in the popup), but
`web/app/settings/page.tsx` still independently auto-generates a token for
every browser on load and centers the UI around copying *that* token out —
which is backwards on mobile (no extension exists there to paste into) and
confusing on desktop (two separate places mint codes, unclear which one is
"real").

Goal: **web never mints a sync code.** It only accepts a code you already
have (from the extension) and links to it. Once linked, Dashboard/Study
already read straight from Firestore (no code change needed there) — the
only broken piece is Settings' generate/regenerate UI.

## Design

- **Extension stays the only place that creates a code** (already done this
  session in `extension/src/popup.tsx`).
- **Web Settings becomes a pure "enter your code" flow**: no auto-generated
  token, no Regenerate. Paste a code → `linkToken()` saves it to this
  browser's `localStorage` and marks it linked. Nothing is written to
  Firestore by web — `linkToken` stops creating the account doc.
- **Same-browser convenience**: if the extension is installed in *this*
  browser, Settings can ask it (via `web-bridge.js`) what code it currently
  has linked. When the pasted/linked code matches the extension's own
  `syncToken`, show a "Sync now" button that tells the extension to run its
  sync cycle immediately instead of waiting for the 5-minute alarm. Web
  never sets or overwrites the extension's `syncToken` — read-only check.
  If there's no extension, or its token doesn't match, no "Sync now" is
  offered — just a note that syncing happens automatically once the
  extension picks up the code (background alarm / on-change sync, already
  built).

## Changes

### 1. `web/lib/auth.ts`
- Delete `TOKEN_WORDS`, `randomToken`, `generateToken`, `createAccountDoc`,
  `regenerateSyncToken`. Web no longer generates or writes account docs.
- `linkToken(token)`: keep validation (`isValidToken`) and
  `setLocalToken`/`markLinked`, but drop the `tokenExists`/`createAccountDoc`
  call — just link locally. (Per your call: don't create the doc from web;
  rely on "Sync now" / the extension's own `ensureAccountDoc` instead.)
- `useSyncToken()`: `token` starts as whatever's in `localStorage` (or
  `null`) and **stops auto-generating** when null. Drop the
  generate-on-mount effect and the `loading` state tied to it — this
  becomes a synchronous localStorage read, no async init needed.
  `linked`/`isLinked` logic is unchanged.
- Keep `isValidToken`, `getLocalToken`, `isLinked`, `markCurrentTokenLinked`
  (still useful — e.g. if we later want "confirm" semantics) as-is.

### 2. New: web ↔ extension "what's your token / sync now" bridge
- `extension/src/web-bridge.js`: add handlers for two new message types
  (mirroring the existing `DUSUBS_GET_WORDS` pattern):
  - `DUSUBS_GET_SYNC_TOKEN` → reads `syncToken` from `browser.storage.local`
    and replies `{ type: 'DUSUBS_SYNC_TOKEN', token }`.
  - `DUSUBS_SYNC_NOW` → forwards to background via
    `browser.runtime.sendMessage({ type: 'dusubs-sync-now', token })`
    (only send if a token is provided; page should only do this when it
    already confirmed a match).
- `extension/src/background.js`: add a `dusubs-sync-now` case to the
  existing `onMessage` listener (alongside `dusubs-delete-word`) that
  re-reads the stored `syncToken`, confirms it equals `msg.token` (defense
  in depth — never sync to a token the extension doesn't itself hold), and
  calls `runSync()`.
- `web/lib/extension.ts`: add `getExtensionSyncToken()` (same
  postMessage/retry pattern as `getWordsFromExtension`, listening for
  `DUSUBS_SYNC_TOKEN`) and `requestSyncNow(token)` (fire-and-forget
  `postMessage({ type: 'DUSUBS_SYNC_NOW', token })`).

### 3. `web/app/settings/page.tsx`
Rework the "Extension Sync Token" section:
- **Unlinked state**: single input (empty, placeholder like
  "quiet-tiger-orbit — paste the code from the extension"), a "Link" button
  calling `linkToken(tokenDraft)`. No auto-filled value, no Copy, no
  Regenerate.
- **Linked state**: show the linked code as read-only text (not an editable
  input) plus an "Unlink this device" button (clears local token/linked
  flag, returns to the unlinked input state). No Copy/Regenerate — web
  never needs to hand this code to anything since it doesn't generate one.
- **Sync now**: on mount (and after linking), call `getExtensionSyncToken()`
  once. If it resolves and equals the linked token, show a "Sync now"
  button next to the linked-code display that calls `requestSyncNow(token)`
  and shows a brief "Syncing…" → "Synced" acknowledgement (no need to wait
  for a real completion signal — same fire-and-forget style as delete).
  If no extension / mismatched token, show nothing extra — words will
  appear once the extension's own background sync picks it up.
- Update the explanatory copy: "Generate a code in the DuSubs extension
  popup, then paste it here to link this device" instead of the current
  "a token was generated automatically for this browser" text.
- Danger zone section (`Clear words (extension)` / `Clear words (ext +
  cloud)`) is unaffected — leave as-is.

### 4. `web/app/dashboard/page.tsx`, `web/app/study/page.tsx`
No changes expected — both already just consume `useSyncToken()`'s
`token`/`linked`/`loading` and fall back to extension-local words when
unlinked. Worth a quick re-read after `useSyncToken` changes shape (loading
semantics simplify) to confirm nothing depended on the old auto-generate
timing.

## Verification
- `npm run build` (extension popup/content bundles) and `cd web && npx tsc
  --noEmit` both clean.
- Manual walkthrough (or note for the user to do so, since this needs a
  loaded extension + real Firestore):
  1. Fresh browser, no extension: open `/settings` → sees empty input, no
     token shown, no Sync now.
  2. Same browser: open the extension popup, hit Generate, Copy.
  3. Paste into `/settings` input, blur/Link → shows linked read-only code.
     Since this is the same browser as the extension and tokens match,
     "Sync now" appears; clicking it triggers a sync cycle (check extension
     service worker console logs for `syncWords: starting cycle`).
  4. Different browser/device: paste the same code into its `/settings` →
     links locally, no Sync now (no matching extension), Dashboard shows
     Firestore words once the first browser's extension has synced.
