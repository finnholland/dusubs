## some thoughts (resolved)
- should the extension just save to firebase from day one?
  - **decided: no.** keep local-first writes (browser.storage.local) with the
    existing background alarm + on-change sync pushing to Firestore. Instant
    local save keeps the hot save-while-watching path fast/offline-safe;
    cross-device latency (up to ~5min) is an acceptable tradeoff.
- how should deleting work — clear extension/clear all but also individual
  delete in dashboard?
  - **decided: keep as-is.** individual deletes already push immediately
    (background.js pushDeletedWord / web deleteWord). No tombstones — a
    word deleted while the other side is offline can reappear on next sync
    (documented limitation in sync.js), acceptable given low write volume.
- can users change sync token (collision detection, delete passphrase)?
  - **decided: keep 1FA, token-only.** token generation already retries on
    collision (auth.ts generateToken). No passphrase — matches the
    intentional share-link trust model documented in firestore.rules.
